# 04 持久化、资源与服务端

只有你的插件**要存东西 / 带自己的文件 / 要开接口**时才需要这一节。

## 一、持久化：只用 host.storage

```js
// 存（值必须能 JSON 序列化）
host.storage.set('state', { seen: '2026-10-24', n: 3 });

// 读（第二个参数是不存在时的默认值）
const st = host.storage.get('state', {});

// 其它
host.storage.remove('state');
host.storage.keys();   // 本插件自己的键
host.storage.all();    // 本插件的全部数据
```

规则：

- **不要用 `localStorage`**（D2）：那样数据不落 `data/`、不跨设备同步、停用也不清理。
- **不要读写宿主的业务键**（`elaina_open_*` 之类）：那是宿主的数据，插件碰它等于绕过 host API。
- 存储按插件 id 分区，**单插件上限 1MB**，超限 `set` 会 throw —— 别往里塞图片 / 模型。
- 值要 JSON 可序列化（函数 / DOM 节点 / undefined 都会坏）。
- **第一次写要等 `app-ready`**：页面脚本求值阶段宿主存储还没读完，此时写入可能用空数据覆盖真实记录。

```js
let ready = false;
host.on('app-ready', () => { ready = true; loadFromStorage(); });
function save() { if (ready) host.storage.set('state', st); }
```

## 二、插件自己的资源：只用 assetUrl

```js
const img = host.assetUrl('img/icon.png');      // → /mods/<真实目录>/img/icon.png
const base = host.assetBase();                  // → /mods/<真实目录>/
const css = host.injectStyle('extra.css');      // 额外样式表，停用真正失效
```

- **绝对不要手写 `/mods/<id>/…`**（D1）。安装目录名是包名（`my-plugin-1.0.0`），
  `id` 与它不一致时自拼路径必 404。
- `assetUrl` 只接受插件目录内的相对路径；`../`、绝对路径、外链一律返回空串。
- `manifest.styles` 里列出的样式表由宿主统一注入 / 停用，不需要再 `injectStyle` 一次。

## 三、服务端半边（可选）

只有需要"插件自己的 `/api` 接口 / 用户上传到插件目录 / 把插件目录当静态资源发出去"时才写。
**服务端半边是在服务端进程里执行第三方代码**，能力必须声明、取用即校验（D19）。

```js
// mods/my-plugin/server.mjs
export async function register(ctx) {
    // ctx.modId / ctx.dir / ctx.log / ctx.json / ctx.readJson / ctx.capabilities()
    ctx.route('GET', '/api/my-plugin/ping', (req, res) => {
        ctx.json(res, 200, { ok: true });
        return true;
    });

    // 用户上传目录：只有声明了 upload-write 才能拿到
    // const up = ctx.uploadDir('my-uploads');

    // 静态目录：只有声明了 static-read 才能拿到
    // const assets = ctx.staticDir('/my-plugin/assets');
}
```

对应的 manifest：

```json
{
  "server": {
    "entry": "server.mjs",
    "capabilities": ["route-register"],
    "routes": ["/api/my-plugin"]
  }
}
```

必须守住的几条：

| 规则 | 为什么 |
| --- | --- |
| 路由路径必须落在 `routes` 声明的前缀内 | 用户看清单就知道插件会占哪些地址 |
| 用 `ctx.utils` / `ctx.route` / `ctx.uploadDir` / `ctx.staticDir` 前先声明能力 | 没声明会 throw（不是静默空实现） |
| `register()` 里不要做长阻塞 | 宿主对 `import(entry)` 与 `register(ctx)` 都有超时（15s / 20s） |
| 不要把用户上传的 `.html` / `.svg` 当 `text/html` 发出去 | 同源渲染 = XSS；`static` 默认按 `application/octet-stream` 发 |

## 四、数据 / 资源放哪儿

| 内容 | 位置 | 怎么访问 |
| --- | --- | --- |
| 插件自己的小状态 | `host.storage` | `host.storage.get/set` |
| 插件自带的图片 / 样式 / 模型 | 插件目录内（如 `img/`、`assets/`） | `host.assetUrl('img/x.png')`；要给插件自己之外用（如 AI 访问）再声明 `server.static` |
| 用户上传的内容（模型、图片） | 插件目录内，由 `server.uploads` 声明的子目录 | `ctx.uploadDir('名字')` 拿绝对路径；客户端经自己的 /api 路由写入 |
| **不要**放的地方 | `web/`、`data/`、宿主源码 | 会覆盖宿主文件、污染用户数据 |

## 五、依赖别的插件

```json
{ "after": ["elaina-avatar"] }
```

```js
const av = host.require('elaina-avatar');
if (av && av.ok && av.api) {
    const url = av.api.url('img/p_calm.png');   // 对方用 assetUrl / 导出 api
} else {
    host.warn('缺少前置插件，降级运行：', av && av.reason);
}
```

- `after` 里的前置没装 / 加载失败 → 本插件**拒绝加载**（`blocked`，卡片上写明原因）。
- 反过来，本插件运行时，前置**不能被单独关闭或卸载**（宿主会弹窗让用户先关依赖方）。
- 前置只是"别人的 api"，**不要**去读对方的 `window.xxx` 私有全局名。
