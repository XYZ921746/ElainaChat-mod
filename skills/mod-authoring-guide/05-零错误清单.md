# 05 零错误清单

交付前逐条过。每条都写明了**怎么判定**（能把"我觉得没问题"变成"我可以验证"）。

## 一、红线自查（违反即返工）

| 规则 | 判定方法 | 常见形态 |
| --- | --- | --- |
| D1 资源路径 | 插件 JS 的非注释代码里**没有** `'/mods/'` 这种字符串拼接 | `'/mods/' + id + '/img/x.png'` |
| D2 持久化 | 全文没有 `localStorage` / `sessionStorage` | `localStorage.setItem('x', …)` |
| D4 私有全局 | 全文没有 `window.__xxx =` 赋值 | `window.__myPluginInit = fn` |
| D5 平台分支 | 全文没有 `isNativePlatform` / `Capacitor.isNative` | 判断"是不是手机端"来自行分支 |
| D6 工厂只做注册 | `register(id, factory)` 的工厂体里没有 `fetch(` / `XMLHttpRequest` / `setInterval` / `setTimeout`，也没有往 `document.body` 或宿主元素写 DOM | 工厂里起轮询、工厂里 `document.body.appendChild` |
| D8 注释 | 新增行里没有变更史词：`★ 20`、`用户要求`、`实测踩到`、`踩过`、`原先`、`旧版`、`改回`、`以前`、`第一版`、`已搬到`、`旧实现`、`新实现`、`迁移前`、`迁移后`、`历史原因`、`曾经` | 注释里写"原先这样做，后来改了" |
| D18 能力组 | 用了 `host.theme` / `host.unlock` / `host.dragSort` / `host.openFolder` 就必须在 `manifest.capabilities` 里声明对应组 | 没声明 → 运行时 TypeError |
| D19 服务端能力 | `server.mjs` 里用到 `ctx.utils` / `ctx.route` / `ctx.uploadDir` / `ctx.staticDir` 前，`manifest.server.capabilities` 都声明了 | 没声明 → 装载失败 |
| D20 失败呈现 | 插件自己的错误不弹全局 alert，只在卡片上让宿主呈现 | `host.alert(插件内部的错误)` |
| 放对位置 | `SKILL.md` 在 `skills/<id>/`；插件在 `mods/<目录>/`；两者不要混 | 把插件当技能装 |

> 判定栏的完整词表以 `AGENTS.md` 为准；本表只是摘要，冲突时以 `AGENTS.md` 为准。

## 二、契约自查

- [ ] `manifest.id` 合法（ASCII、字母数字 `- _ .`、不以 `.` 开头）
- [ ] `manifest.id` 与 `register(id, …)` 的第一个参数**一致**
- [ ] `scripts`（如有）排在 `entry` 之前能工作 —— `entry` 引用它们定义的函数
- [ ] `defaultEnabled` 只在确实该默认开启时写 `true`
- [ ] `after` 里写的 id 都是真实存在的插件，且本插件能接受"缺了它就不加载"
- [ ] 用到的每个插槽名都在那 6 个之内（拿不准就 `host.slots()`）
- [ ] 用到的 host API 名字都拼对了（对照 `03-契约速查.md` 的 A2）
- [ ] `host.slot` 的 spec 字段齐全（`id` / `label` / `render` 各插槽见 A5）
- [ ] 用到的能力组都在 `manifest.capabilities` 里
- [ ] `server` 声明里的 `routes` / `uploads` / `static` 与代码里实际用的一致

## 三、生命周期自查

- [ ] 工厂**只做注册**；动作放在 `setEnabled(true)` 或按钮回调里
- [ ] 定时器 / 轮询起在 `setEnabled`，停用时要清掉（否则关掉插件还在后台跑）
- [ ] 停用后再启用**不会重跑工厂** —— 工厂里的 DOM 引用、定时器 id 都还在，要判空复用
- [ ] 长任务（`fetch`、轮询）监听 `host.signal` 的 abort，卸载时退出
- [ ] 写 `host.storage` 之前确认已经等到 `app-ready`
- [ ] `setPromptHint` 是**覆盖**语义 —— 需要多段内容时自己拼成一段再传一次
- [ ] 停用时该退订的事件 / 该摘的 DOM，交给宿主回收（用 `host.on` / `host.slot`），不要自己藏 DOM

## 四、用户体验自查

- [ ] 插件卡片上的 `README.md` 写了"做什么 / 怎么用 / 已知限制"
- [ ] 失败时给出可读原因（`host.warn` / `host.log` 用中文写清楚），不要静默失败
- [ ] 没有当前对话等前置条件不满足时，用 `host.alert` 明确说一句，而不是"点了没反应"
- [ ] 不替用户做"关别人的插件 / 删别人的数据"这类动作
- [ ] 手机端（APK）不可用的功能要么隐藏，要么明确提示 —— 不要写平台分支去猜（D5）

## 五、验证

1. 设置 → 插件 → 打开开关：卡片应是「已加载」。
2. 看控制台 `[Mod:<注册名>]` 日志：没有 error / warn。
3. 关掉开关：界面里的贡献应该全部消失（插槽项、样式、提示词）。
4. 刷新页面：已启用插件自动恢复，不出现双份界面。
5. 有服务端半边时：`/api/<你的前缀>/…` 能通；把错误的能力声明删掉应会装载失败（说明守卫生效）。
6. 有资源时：`host.assetUrl(...)` 在浏览器里能取到 200（不是 404）。

## 六、提交前

- 改的是插件与技能内容时，**不要**顺手改宿主（`web/js/`、`server/`）—— 需要宿主能力时提需求。
- 若确实必须改宿主（例如要新插槽），那是另一类改动：按 `AGENTS.md` 走 D7 / D16 / D18 / D20，并同步 `开发文档.md`。
