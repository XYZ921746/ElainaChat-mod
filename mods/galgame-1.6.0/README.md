# Galgame 界面

全屏沉浸式剧情界面：场景背景 + 立绘 + 打字机对话框，内置 **「情景演绎」**（全屏 Live2D 互动）。
与主界面**共用同一份对话数据**。

> 原独立的「Live2D 视频通话」插件已并入本包（2026-10）：两者是同一件事的两种呈现，
> 拆成两个包时要开两个开关、市场里还要装两次。现在**一个包、一个开关**，
> 主界面顶栏的入口叫「情景演绎」。

## 依赖

需要先启用三个前置（缺任一个本插件会被**拒绝加载**，设置 → 插件 里会标明原因）：

| 前置 | 提供什么 |
| --- | --- |
| **伊蕾娜立绘与情绪**（`elaina-avatar`） | 立绘与情绪识别 |
| **场景背景图**（`scene-backgrounds`） | 31 张场景背景 |
| **Live2D 引擎与模型**（`live2d-models`） | 情景演绎用的运行引擎、模型清单与模型管理界面 |

> 这些资源**不在本包里**（2026-10 搬到独立资源包）—— 用它们的不只是剧情界面。
> 留在本包里会变成"想要背景就得启用剧情界面"，而且卸载时会一起带走。

## 怎么用

1. 设置 → 插件 → 打开「Galgame 界面」（上面三个前置会在启用时被自动拉起来）
2. **启用不等于自动全屏**：回到主页，点右上角的「情景演绎」进入舞台（界面里可退出）
3. 第一次用之前，点插件卡片上的齿轮 →「情景演绎」，在 **① 角色呈现** 里选：
   - **Live2D 模型** —— 会动、有口型；在 ② 里选模型（上传 / 重命名 / 删除在「Live2D 引擎与模型」）
   - **图片立绘** —— 按情绪换立绘，不加载引擎，低配设备更省电（需要「伊蕾娜立绘与情绪」）
4. 同一页里还能改舞台背景（上传 / 从场景背景图里挑）、开关打字机、直接打开测试

## 特性

- **一个舞台，两种角色呈现**：图片立绘 ↔ Live2D 模型，设置里切一下立刻生效
- **31 张场景背景**（来自 `scene-backgrounds`），也可以上传自己的图
- 对话框：打字机、回车发送，与主界面共用同一份对话数据
- 立绘随 AI 回复的情绪自动切换（走 `elaina-avatar` 的情绪词表）；Live2D 还会带口型、鼠标跟随、可调大小与位置
- **情景演绎**：全屏 Live2D 模型、口型同步、AI 表情/动作/情绪驱动

## 情景演绎：AI 能驱动它做什么

模型回复里带这些标签即可（标签不会显示给用户）：

```text
[情绪:开心]  [表情:脸红]  [动作:挥手]  [位置:left]  [大小:大]  [背景:深蓝]
[操作:打开视频通话]  [操作:结束通话]  [操作:静音]  [操作:隐藏水印]
```

> 这些是**宿主**提供的标签（开关舞台、静音、水印），不属于舞台 UI ——
> 舞台本身只有右上角的退出按钮，没有通话那套控件（挂断 / 正在说话 / 静音提示）；
> 也没有模型下拉：换模型到「设置 → 插件 → Galgame 齿轮 → 情景演绎」里选。

图片立绘模式下，`[情绪:]` 与 `[表情:]` 都会换立绘（同一套同义词表），`[动作:]` / `[位置:]` / `[大小:]` 不生效。
Live2D 模式下可用表情/动作由**当前模型**决定，系统提示词会自动注入该模型真实的表情与动作文件名。

### 随附技能：情景演绎

包内带一份技能（`skills/scenario-stage/SKILL.md`，manifest `skills` 声明），
告诉 AI：两种呈现各能用哪些标签、背景有哪些名字、什么时候该主动换。
AI 通过能力索引里的 `skill:` 条目发现它，用 `agent_help` 取正文 —— 不需要用户手动教。

### 给 AI / 外部的接口

舞台把"能调什么"暴露在 `window.Live2DCall` 上（标签通道与设置页走的是同一套实现）：

| 接口 | 作用 |
| --- | --- |
| `listBackgrounds()` | 返回 `{ presets: [...], scenes: [...] }`，AI 据此知道能说哪些背景名 |
| `setBackgroundByName(name)` | 按名字换背景（预设色或场景图），认不出返回 `false` |
| `listEmotions()` | 情绪键清单（立绘与模型共用） |
| `setEmotion(name)` | 换情绪/表情：立绘换图、模型换表情 |
| `getSceneMode()` / `setSceneMode('live2d'\|'portrait')` | 读/切当前呈现方式 |
| `setBackground(css)` | 直接给 CSS（内部会过白名单） |

**两种模式都支持**：背景由舞台的 CSS 背景承担，与用不用引擎无关；表情在立绘模式下映射成对应立绘，
在模型模式下驱动 exp3 / 参数。

## 情景演绎设置

| 区块 | 说明 |
| --- | --- |
| ① 角色呈现 | 图片立绘 / Live2D 模型，二选一；切成立绘后不加载引擎 |
| ② Live2D 模型 | 选当前模型、鼠标跟随开关与幅度、重置大小位置；上传 / 删除在「Live2D 引擎与模型」 |
| ③ 舞台背景 | 上传图片 / 从场景背景图里挑 / 清除；不设置就用剧情场景或纯色 |
| ④ 对话框 | 打字机开关（关闭则整段直接出现） |
| ⑤ 试一下 | 直接打开情景演绎，看到的就是对话里的样子 |

## 语音（前提：先在「设置 → 语音」里配好）

舞台的语音是**复用宿主那套**，插件里没有任何开关或副本：

| 能力 | 配置位置 | 舞台上的表现 |
| --- | --- | --- |
| 朗读回复（TTS） | 设置 → 语音 → TTS 供应商 + API Key | 新回复**自动念出来**，没有开关（配了就念，没配就只显示文字） |
| 语音输入（ASR） | 设置 → 语音 → 语音识别 → 阿里百炼 / 小米 MiMo + Key | **聊天框那一行、发送键左边**的 🎤：点一下开始说，再点（变 ⏹）结束，识别完**自动发送**；未配置时按钮隐藏 |

两者都走宿主的同一条链路：朗读与"播放这条消息的语音"共享播放器（会抢占、有缓存）；
识别结果与主输入框走同一条发送链路（记忆、续跑、TTS 都照常）。
插件通过 `host.speak` / `host.dictation` 调用，不直接摸宿主的内部函数。

## 技术说明

| 文件 | 作用 |
| --- | --- |
| `index.js` | 剧情界面（装配入口；同时把情景演绎挂起来） |
| `index-live2d.js` | 情景演绎实现主体（渲染、口型、表情/动作驱动、模型尺寸调整） |
| `register.js` | 情景演绎的装配（顶栏按钮 + 设置窗插槽），由 `index.js` 调用 |
| `settings-panel.js` / `panel.html` | 情景演绎设置面板的行为与结构 |
| `skills/scenario-stage/SKILL.md` | 随附技能：告诉 AI 怎么调背景与表情 |
| `style.css` | 剧情界面 + 设置面板样式（随插件启用/停用） |

几个容易踩的点：

- **注册点只有一个**（`index.js`）。`index-live2d.js` / `settings-panel.js` 只暴露
  `window.__live2dInitXxx` 函数 —— 多调一次 `ElainaMods.register` 会**覆盖**主界面，
  表现为"插件 ready 但剧情界面没了"。
- `manifest.scripts` 列出的文件**先**注入，`entry` **最后**注入 ——
  装配文件要调用其它文件定义的东西，顺序反了会拿到 undefined。
- **提示词只有一段**：`host.setPromptHint` 在同一插件内是覆盖而不是拼接，
  所以场景说明与 Live2D 表现指南由 `index.js` 的 `syncSceneHint()` 合成一次注入。
- 背景图走 `host.require('scene-backgrounds')`、立绘走 `host.require('elaina-avatar')`、
  引擎与模型走 `host.require('live2d-models')` —— 都不自己拼图片/脚本路径，
  用户改了那些包的目录名也不会 404。
- 引擎**懒加载**：`window.ElainaLive2DModels.ensureEngine()` 在真正打开情景演绎时才注入
  那三个库（不用的用户不必为 787 KB 付代价）。
- 情景演绎的实现主体挂 `window.Live2DCall` —— 宿主有约 30 处 `window.Live2DCall?.xxx`
  调用点（语音口型、Agent 表情），保留这个名字它们就一行都不用改。
- 情景演绎的设置键统一在 `galgame.live2d.*` 下（原 `live2d.*` 会在加载时一次性迁移过来）。

## 已知限制

- 点右上角「✕」退出舞台只收起界面，**不会停用插件**；插件开关仍在设置 → 插件里
- 背景是 `.jpg`，且清单（`scene-backgrounds/index.js` 的 `BGS`）需与图片文件一一对应
- 部分 Live2D 模型没有绑定眉毛 / 微笑参数，情绪里的"皱眉""挑眉"在那类模型上无法表达
- Live2D 在手机（APK）端未实测
