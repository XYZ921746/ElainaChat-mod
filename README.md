# ElainaChat mod（Go 服务端版）

> 本目录是 **Go 服务端版本**，仓库里只有这一套服务端实现：启动脚本、Windows 打包与开发文档都以 `server/` 为准。

本地优先的 BYOK AI 角色聊天应用。程序本体只内置**文字聊天 + Agent 能力**，角色的呈现方式与界面细节交给**可装可卸的扩展包（mod）**：宿主不认识任何具体插件，插件只通过一份收窄的 host API 与固定的宿主插槽接入。

- **Go 单文件服务端**：服务端是静态编译的 Go 二进制（`server/`），不需要随包携带 Node 运行时；前端仍是零构建的原生 ES 模块。源码运行只需 Go 1.27+，不需要 `npm install`。
- **BYOK，数据全在本机**：接入你自己的大模型 API Key，请求从本机直接发给服务商；没有作者网关、共享套餐或内置密钥。
- **mod 优先**：扩展包决定立绘、Live2D、桌宠、场景背景、情景演绎（galgame）等呈现；装了坏插件会被隔离并写盘自动停用，只在那张插件卡片上说明原因，不影响宿主与其它插件。Windows 桌面壳还允许插件申请**原生透明置顶窗**（桌宠浮在桌面上、可拖动、可点开菜单）；纯浏览器里该能力不可用，插件自带兜底。
- **Agent 操作**：模型可以读写文件、执行命令、操作手机（点击 / 滑动 / 输入 / 截图 / 读通知短信通讯录日历）、写日记记忆（如 `recall_search` 凭日记找回历史原话）、创建定时任务；操作说明书按需下发，权限分档。
- **手机 Agent 操作可靠**：「打开应用」按已装应用解析应用名并以前台应用核对结果；游戏等无控件树的画面自动叠加屏幕坐标网格；应用内状态条与系统悬浮条按前后台自动切换；「停止」立即生效、迟到的旧回复作废（机制细节见 [开发文档](开发文档.md) §3.1）。
- **手机读取类信息只认系统权限一道闸**：应用内不设开关（撤销只能去系统设置），设置页提供「摘要 + 一键授权」与权限明细浮层。
- **推理型网关兼容**：对强制开思考、行为严格的网关做了适配——续跑输出预算独立放宽、思考参数按网关反馈自适应、模型调用有硬死线、空输出自动放宽重试，普通聊天与手机 Agent 都可用。
- **AI 联网搜索与浏览器**：需要"现在的事实"时 AI 自己去搜（内置 **Tavily**，另有**自定义搜索源**），或者真的开一个独立浏览器窗口看页面、点按钮、填表单。
- **MCP 客户端**：在「设置 → 扩展 → MCP」里加一台 MCP 服务器 —— 远程服务填一个 `https://…/mcp` 地址（Streamable HTTP），本地服务填一条启动命令（stdio），它提供的工具会自动出现在 AI 的能力清单里。只做客户端方向 —— **不会**把本机的文件与命令执行能力暴露出去。
- **语音**：云端 ASR 识别（阿里百炼 / 小米 MiMo）与多服务商 TTS（MiMo / MiniMax 克隆音色 / 千问 Qwen-TTS / 兼容 OpenAI TTS）。
- **自带访问控制**：端口对谁可达由 `data/config.json` 的 `host` 决定（默认 `127.0.0.1` 仅本机；改成 `0.0.0.0` 即对局域网开放——无密码时开放就是对局域网完全开放，这是配置文件里管理人员的显式选择）。设置访问密码后所有设备（含本机）打开应用都需要登录；无密码态没有闸门也没有登录页。密码只以明文写在 `data/config.json` 的 `password`，在设置里修改也写回这里（哈希只派生在内存里，`data/auth.json` 会被删除，不作为持久形态）；规则为至少 8 位、同时包含数字和其他字符（字母或符号），不再强制大小写；有强度校验与三层防爆破。服务端在同一端口同时支持 HTTP/HTTPS（局域网页面自动跳 HTTPS，自签证书首次访问需点「高级 → 继续前往」）；端口、HTTPS 开关与自定义证书也在同一份配置里。
- **数据备份与局域网共享**：在「设置 → 高级设置 → 我的数据」导出 / 导入标准 zip（`data/` + `mods/` + `skills/`）；同一局域网的两台设备也能直接开启共享、用 IP / 端口与**对方的访问密码**互相拉取，不必先拷文件（共享窗口 5 分钟，临时端口只放行登录与导出；两端实例都需设过访问密码）。
- **版本检测**：设置 → 高级设置「版本与更新」直接查 GitHub 仓库的最新 Release；按当前运行形态（手机版 APK / 桌面版 exe / 电脑版源码）给出对应安装包，更新说明按 Markdown 渲染（与插件 README 同一套渲染器），**只提示与下载，不自动替换程序**。GitHub 被 hosts / DNS 指偏时自动改用公共 DNS 解析真实 IP 直连（证书仍按 api.github.com 校验，不改系统设置）。
- **PWA**：浏览器打开后点顶栏「安装」，即可装成桌面独立应用。

## 特性

- **人设与对话**：一张人设卡一文件，可新建 / 复制 / 改名 / 删除并随时切换；**每个对话还能单独绑定人设卡与对话模型**（不绑则跟随全局），并可为该对话改 AI 的名字与头像；消息渲染支持 Markdown 与 LaTeX（公式走 KaTeX，渲染器自带转义，原始 HTML 一律当字面量）。
- **记忆**：每过若干轮自动写一篇日记（也可以点「立即整理记忆」手动整理），聊天时按需检索；整理用的模型在「设置 → 能力 → 记忆与检索」里选，召回用的嵌入 / 重排序模型也在同一张卡（各类模型本体在「设置 → 模型」分栏添加与管理，分为对话 / 语音转文字 / 文字转语音 / 嵌入 / 重排序）（关闭 / 沿用当前对话模型 / 从已添加的对话模型指定），另有金句 / 语笺 / 收藏。
- **主题**：暗夜魔女书房（默认）/ 暖米绿 / 雾蓝日系 / 石墨玻璃；显示模式另有**浅色 / 深色 / 跟随系统**三档。主题偏好会在首帧前回放，刷新不再先闪一下默认浅色。
- **移动端界面**：窄屏是独立的一套外壳 —— 底栏「对话 / 回忆 / 我的」、首页直接管对话（长按菜单、多选、分类文件夹、拖拽排序）、回忆四页共用分段条、设置按分区下钻到二级页；插件插槽与业务逻辑与桌面端共用。
- **定时任务**：对 AI 说"每天给我发消息 / 明天提醒我…"，它用 `[任务:…]` 建立任务，到点以角色身份主动给你发消息。安卓版上任务靠应用内轮询触发，需在「设置 → 能力 → 手机权限」里允许自启动、加入电池优化白名单，并在最近任务里锁定后台，应用被清掉后才叫得醒。
- **成就系统**：事件成就（如 10 月 17 日「星屑之日」生日纪念）与进度成就两类，解锁后持久保留 —— 删掉几段对话，已拿到的成就也不会被撤销。
- **BYOK 直连**：支持 OpenAI 兼容（DeepSeek / 硅基流动 / OneAPI / Ollama…）、Anthropic、OpenAI Responses 三种对话协议，可填自己的 Base URL；可以配多个提供商、每家勾选多个模型，选一个默认模型并设置失败回退顺序（设置 → 模型：总览 / 我的模型 / 使用偏好）；各家 API Key 分开存。
- **AI 权限分档**：「关闭 / 逐条确认 / 自动通过（禁止删除）/ 完全访问（含删除）」四档，前三档同时管电脑与手机。
- **局域网访问**：把 `data/config.json` 的 `host` 改成 `0.0.0.0` 并重启，手机 / 平板用局域网地址打开；设置访问密码后凭密码登录（在设置页或 `data/config.json` 里设置），无密码态不设闸门、直接可用。
- **同时开多个实例**：给每个实例配独立的 `DATA_DIR` 与端口（例如 `DATA_DIR=/path/data2 PORT=4101`），即可在同一台机器上并行运行。会话凭据按实例隔离（cookie 名带实例后缀、token 内含实例 ID），在浏览器里各登各的、互不踢下线；两个实例共用同一个 `DATA_DIR` 不受支持 —— 聊天数据与记忆索引会被互相覆盖。
- **软件内日志**：时间 / 模块 / 级别 / 正文分色显示，可按级别与模块筛选、可导出；控制台同一套配色。敏感字段（含 API Key）落盘前脱敏。

## 下载与安装

到 [Releases](https://github.com/XYZ921746/ElainaChat-mod/releases/latest) 下载对应平台的包：

### 电脑版（WebView2 外壳，推荐）

下载 `ElainaChatMod-Setup.exe` 安装，或直接解压便携版 zip。安装包会创建开始菜单与桌面快捷方式，卸载时可以选择保留聊天数据；**不需要**安装 Node.js 或 Go，也**不需要**构建。包内结构：

```text
ElainaChat Mod/
├─ ElainaChat Mod.exe    # WebView2 外壳：自动拉起服务端并打开界面，托盘常驻
├─ server/elaina-server.exe  # 静态编译的 Go 服务端（单文件，无运行时依赖）
├─ shell.json            # 外壳配置（入口 server\elaina-server.exe、端口）
├─ app/                  # 前端本体（web/、skills/ …）与 app\data\
└─ README.md             # 便携版使用说明
```

- 数据在 `app\data\`，与服务日志 `app\logs\server.log` 一起随目录移动。
- 关闭窗口 = 最小化到托盘，托盘右键「退出」才是真正退出；任务管理器只需结束 `ElainaChat Mod.exe` 一个，后台服务随之退出。
- **桌面版系统要求**：需要 .NET Framework 4.8 与 WebView2 运行时的支持，Windows 10 1903 以后的版本一般自带（缺失时外壳会提示初始化失败）。**不建议 Windows 10 1903 以前的系统运行桌面打包版本**——网页版与安卓版没有这些要求。

### 安卓版

下载 `ElainaChat-mod-x.y.z-arm64-v8a.apk`（仅 arm64-v8a；debug 构建另带 x86_64 供模拟器用），在手机上允许「安装未知来源应用」后安装。APK 把 `web/` 打进 WebView，服务端是**同一个 Go 单文件**，在 `:node` 独立进程里从原生库目录直接执行 —— 不再内嵌 Node 运行时。Go 侧在 service mode 暴露完整的 `/api/store`、`/api/data/*`、`/api/data/lan/*`、`/api/memory/*`、`/api/agent/*` 等接口；页面只按 `NODE_FIXED_PREFIXES` 转发一部分（日志 / 记忆 / 鉴权 / 插件路由），store/data/LAN 由各适配层用绝对 `__nodeBase` 直连。构建开关 `ELAINA_LOCAL_SERVER`（默认开）决定是否打包服务端；关掉时聊天数据只能读 `store.cache.json`（只读），备份 / 局域网共享也不可用 —— 需要保存数据的设备不要关闭，只在纯展示/瘦身构建里用。

包名为 `com.elainachat.mod`，与更早的 `com.elainachat.opensource` 包**不兼容**（无法覆盖安装，需卸载重装；卸载会清空数据，请先在旧版导出备份）。

> 包名与发布文件名可能随版本调整，**以 Releases 页面实际列出的文件为准**。

## 从源码运行

```bash
cd server
go build -o bin/elaina-server.exe ./cmd/elaina-server
cd ..
./server/bin/elaina-server.exe
# 浏览器打开 http://127.0.0.1:3999
```

- 需要 Go 1.27+；**不需要** `npm install`，前端没有构建步骤。不想手动编译时直接双击 `启动.bat`：二进制缺失、或 `server/` 下的 Go 源码比二进制新时，它会先问你是否构建（选「构建」后若本机没有 Go 工具链会自动下载安装），再启动。
- 端口以 `data/config.json` 的 `port` 为准（默认 **3999**，填 `0` 由系统分配），启动时只绑这一个端口，被占用就报错退出并提示改配置，不会静默换到别的端口。
- 本项目的另一个实例已经占着这个端口时，不会再起一个服务，只把浏览器指过去然后退出。
- Windows 也可以直接双击 `启动.bat`（会自动打开浏览器）。它同时负责构建与启动：已有可用构建就直接跑，需要构建时先问一次（选「不构建」则直接退出，不会启动过期二进制）。
- 想从源码直跑（改完 Go 代码不用先编译二进制）：`npm start`，或 `cd server && go run ./cmd/elaina-server`。它需要本机 Go 工具链，首次运行要编译并下载依赖。 `proxy.golang.org` 在国内网络不可达时，`go` 每条命令都要先等代理超时（实测 20 秒以上）；把镜像写进 Go 配置即可：`go env -w GOPROXY=https://goproxy.cn,direct`。
- 数据目录 `data/` 首次启动自动生成；想用干净实例，删除 `data/` 后重启即可。

## 装成桌面应用（PWA）

用 `http://127.0.0.1:3999` 打开（用局域网 IP 打开时浏览器不给安装入口，这是安全上下文规则），顶栏会出现「安装」按钮，点一下装成独立窗口的桌面应用。它与浏览器版读写同一份 `data/` —— 服务得在跑，PWA 不是独立后端。卸载只删快捷方式，不动数据。

| 能力 | 电脑版 | 安卓版（APK） |
|---|---|---|
| 文字聊天 / 语音 / 主题 / 人设 / 成就 | 支持 | 支持 |
| AI 操作电脑（读写文件 / 执行命令） | 支持（可访问任意路径，按权限档决定问不问） | 不支持 |
| AI 操作手机（点击 / 滑动 / 输入 / 截图 / 读通知短信通讯录日历） | 不支持 | 支持（读取类信息只由系统权限决定，应用内不设开关） |
| AI 读写手机文件 | 不支持 | 支持（Agent 工作区 + 你授权的一个文件夹） |
| 插件安装 / 卸载 | 支持（丢进 `mods/`、应用内市场或「上传安装」） | 支持（只能应用内市场 / 「上传安装」） |

| 插件的服务端半边（`manifest.server`） | 支持（Go 宿主 `server/internal/plugin` 装载） | 支持（同一个 Go 宿主在 `:node` 进程里装载；关掉 `ELAINA_LOCAL_SERVER` 时回落原生兜底） |
| AI 用浏览器 / MCP 客户端 | 支持 | 不支持（这两项依赖电脑侧的本机服务） |
| 数据备份 | 导出 v4 标准 zip：`data/`（聊天数据 + 记忆逻辑导出）+ `mods/`（插件）+ `skills/`（技能） | 导出到手机存储的 v4 zip（同一套 `/api/data/export`），与电脑版互相导入；插件 / 技能、记忆都保留 |

## 扩展包（Mod）

程序本体只负责聊天与 Agent 能力，呈现方式全在扩展包里。仓库**不包含任何插件源码**：仓库只推宿主本体，插件通过「设置 → 扩展 › 插件 → ✦ 插件市场」安装，也可以「上传安装」一个 zip；电脑版还可以把 zip 丢进 `mods/`。

- **默认关闭**：只有 `manifest.json` 里**显式**写 `"defaultEnabled": true` 的插件才默认启用，漏写一律算关闭 —— 插件会改界面，不该在你不知情时生效。
- **前置依赖**：打开一个插件时，它依赖的前置插件会自动一起打开；前置没装或坏了时它拒绝启动，并在卡片上写明缺什么、该装什么。反过来，有插件正在运行时，它依赖的那个插件不能直接关闭或卸载。
- **失败隔离**：装坏的插件会被自动停用并写盘，下次启动不再重试；原因只显示在那张插件卡片上，不弹全局弹窗、不牵连其它插件。
- **能力要声明**：会碰宿主重能力的插件必须在 `manifest.capabilities` 里逐组声明（主题模板 / 成就 / 拖拽排序 / 打开文件夹 / 桌面置顶窗 / 宿主设置面板），没声明的成员根本不存在；会碰磁盘或网络的服务端半边还要在 `manifest.server.capabilities` 里声明，未声明就取用会直接报错。
- **写插件**：完整指南在 [`skills/mod-authoring-guide/`](skills/mod-authoring-guide/SKILL.md)（快速开始、契约速查、持久化与服务端、零错误清单）；跨边界契约、host API 与插槽清单见 [开发文档](开发文档.md)。

## 技能（Skills）

技能是**给 AI 的指令与知识**（一个目录一份 `SKILL.md`，纯文本），与插件平行但独立：插件扩展的是应用本身（界面、宿主接口、静态资源），技能只进 AI 的资料库，不注册进应用、不参与运行。

- 本地技能放在 `skills/<id>/SKILL.md`，在「设置 → 扩展 → 技能」里查看、上传安装或卸载（与插件同一套 zip 安全规则）。
- 插件也可以随附技能（`manifest.skills`）：技能文件住在插件目录内，卸载插件时随之消失，不需要额外清理。
- 扫描到的技能由 Agent 运行时登记为 `kind: 'knowledge'`：模型先看到一行能力索引，真要正文时再用 `agent_help` 取回 —— 不占普通对话的上下文。
- 仓库自带一份「制作插件」技能（`mod-authoring-guide`），入口只放路线图与红线，细则按需加载。

## 目录结构

```text
ElainaChat-mod/
├─ web/                     # 前端本体（唯一前端编辑入口）与静态根
│  ├─ index.html            # 单页骨架
│  ├─ js/                   # 前端模块（store / core / data / agent / ui / voice / settings / mods / mcp / mobile-shell …）
│  ├─ css/                  # 样式层：base.css 先加载，themes / redesign / layout-full / pages-luxe / mobile-shell / settings 依次覆盖
│  ├─ vendor/               # 宿主自带库（tailwind / KaTeX；Live2D 引擎由 live2d-models 插件自带）
│  ├─ audio/  icons/        # 内置参考音频、PWA 图标
│  ├─ manifest.webmanifest  # PWA 清单
│  └─ sw.js                 # PWA 用的 Service Worker（故意不缓存任何东西）
├─ server/                  # 电脑版服务端（Go：路由 / 数据 / 插件宿主 / 中转 / MCP / 浏览器 / 日志）
│  ├─ cmd/elaina-server/    # 入口（配置、鉴权、证书、监听）
│  └─ internal/             # 各领域包与测试
├─ scripts/                 # 只放验证脚本：npm run check 跑的 check-*.mjs + 共用运行时
├─ skills/                  # 技能目录（给 AI 的纯文本指令与知识；自带 mod-authoring-guide）
├─ mods/                    # 扩展包安装位（插件源码不入库；经应用内市场安装）
├─ data/                    # 运行时数据（主 data + 对话 data，见下）
├─ 启动.bat                 # Windows 双击启动（有可用构建就直接跑；缺失或源码更新时先问是否构建）
├─ 开发文档.md               # 架构、契约表与变更史
└─ package.json
```

- **`data/` 分两层**：`main/` 是软件级记录（设置、密钥、人设卡、记忆、音色样本），`conversations/` 是一个对话一个 JSON。`logs/`、`auth.json`、`instance-id` / `session-key` / `session-epoch`（会话凭据的实例身份与吊销代数）、`cert.pem`/`key.pem`（自签证书）与 `config.json`（端口 / 监听地址 / HTTPS / 自定义证书 / 访问密码）是服务自身的运行件。目录结构见 [`开发文档.md`](开发文档.md) 第 2 节。
- **壳与适配工程入库，打包工具链与签名不入库**：安卓原生工程在 [`dist/Android/`](dist/Android/README.md)（Java / 资源 / Gradle 脚本随仓库走，SDK / NDK / `www/` / 构建缓存被排除）；Windows 壳源码在 [`dist/Windows/`](dist/Windows/README.md)（`shell\` C# 源码随仓库走，工具链与产物留在本机）。**仓库不含一键打包脚本与签名材料**——怎么打包、用什么工具由 fork 者自行决定，两份 README 提供建议流程；release 构建需自备签名（见 `dist/Android/README.md` 的签名章节）。

## 开发

- `npm run check`：运行全部检查模块，清单**以 [`scripts/run-checks.mjs`](scripts/run-checks.mjs) 为准**（`check:serial` 串行跑以便排查模块间干扰，`check:fast` 只跑插件模块）；单个模块可加用例名子串只跑一段，运行器另有 `--only <子串>` / `--jobs N` / `--bail` / `--timeout <秒>`。`check-go` 跑 Go 服务端的编译 / vet / 测试；个别依赖本机环境（Go 工具链、插件实物、模型文件、浏览器）的用例会自动跳过。
- 可数的事实（检查模块数、扩展包数、插槽数、脚本加载数）一律**以对应文件实物为准**，本文不写死数字。
- 本地打包：**仓库不内置打包脚本**，建议流程见 [`dist/Windows/README.md`](dist/Windows/README.md) 与 [`dist/Android/README.md`](dist/Android/README.md)（依赖版本、组装方式、签名与许可要求）。安卓侧的工程自带构建入口：先 `node dist/Android/scripts/sync-web.mjs` 把 `web/` 同步进 `dist/Android/www/` 并交叉编译 Go 服务端，再 `npm install && npm run build:debug`。产物留在本机、不入库；签名材料**绝不入库**，fork 者用自己的签名。
- 架构说明、跨边界契约表、存量违规清单与变更史见 [开发文档](开发文档.md)；变更史按**开发周期**归档，一个周期内的同类改动合并为一条。版本更新公告见 [CHANGELOG](CHANGELOG.md)。

## 隐私与数据

- 聊天记录、设置、API Key 全部存在本地 `data/`，不进仓库、不上传作者服务器；请求由本机直连你填的服务商。
- 访问密码以明文写在 `data/config.json` 的 `password`（唯一持久形态；`data/auth.json` 只在旧版迁移时被读取并删除，哈希仅存在于内存），设置里修改也写回这里；规则为至少 8 位、数字 + 其他字符（字母或符号）。`data/` 已被 `.gitignore` 排除。自签 HTTPS 证书默认在 `data/cert.pem` 与 `data/key.pem`；也可替换这两个文件（或在 `data/config.json` 里指定其它路径），应用不会覆盖 subject 不含应用名的证书。
- 日志写入 `data/logs/`，敏感字段（含各类 API Key）落盘前脱敏；启动日志只说明访问密码是否已设置，不打印明文。
- 手机版数据统一在应用私有目录的 `elaina-data/`（聊天 / 卡片 / 记忆 / 插件开关）；旧版 `filesDir/store.json` 在首次启动时一次性迁入并改名为 `.migrated-*` 保留。API Key 仍走 Android Keystore 加密。
