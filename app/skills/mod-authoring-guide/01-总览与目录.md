# 01 总览与目录

这一节解释**这个技能由哪些文件组成**，以及该按什么顺序读它们。
只想知道"下一步读哪个文件"的话，看第二节的表就够了，不必读完整节。

## 一、文件职责

| 文件 | 什么时候读 | 内容 |
| --- | --- | --- |
| `SKILL.md` | **总是**（入口） | 路线图、渐进加载规则、红线、流程 |
| `01-总览与目录.md` | 想知道全貌时 | 本文件：文件职责、推荐顺序、术语 |
| `02-快速开始与模板.md` | 从零建插件时 | 最小 manifest、工厂骨架、常见坑、zip 打包 |
| `03-契约速查.md` | 填 manifest / 调 host API / 接插槽时 | 字段、API、插槽 spec 的可复制摘要 |
| `04-持久化资源与服务端.md` | 要存数据 / 放资源 / 开接口时 | `host.storage`、资源 URL、`manifest.server` |
| `05-零错误清单.md` | **交付前** | 自查清单、反模式、判定词表 |

## 二、推荐顺序（按需裁剪）

```text
只加一个按钮 / 面板          → SKILL.md → 02 → 03（插槽 sections.tabs / header.actions）→ 05
要记住设置、跨刷新不丢      → + 04（host.storage）
要带图片 / 模型 / 数据文件    → + 04（assetUrl / manifest.server.static）
要有自己的 /api 路由          → + 04（manifest.server.routes + server.mjs）→ 03（A23 能力）
插件依赖另一个插件            → + 03（A1 的 after / hidden、host.require）
```

## 三、术语

| 词 | 含义 |
| --- | --- |
| **宿主** | 应用本体（`web/` + `server/`）。它**不认识**任何具体插件 |
| **插件（mod）** | `mods/<目录>/manifest.json` + 入口脚本；同源执行的第三方代码 |
| **注册名** | `ElainaMods.register('xxx', factory)` 的第一个参数，是插件的**权威身份** |
| **manifest.id** | 清单里的身份，决定依赖匹配与资源 URL 基准；可以 ≠ 目录名 |
| **dir** | 磁盘上的真实目录名（可能是 `galgame-1.0.0` 这种带版本号的） |
| **工厂（factory）** | `register(id, factory)` 的第二个参数。**只做注册**，返回插件的 api 对象 |
| **插槽（slot）** | 宿主挖好的 6 个扩展点，插件只能往这些位置挂东西 |
| **host API** | 工厂收到的 `host` 对象，插件与宿主之间唯一的接口 |
| **贡献（contribution）** | 插件注册的东西（插槽项 / 样式 / 主题 / 提示词 / 事件订阅）；停用即收回 |
| **技能（skill）** | `skills/<id>/SKILL.md`，纯文本资料；与本技能同名但是另一回事 |

## 四、生命周期（插件作者只需要记住这四件事）

1. **加载**：宿主注入 `manifest.scripts`（按顺序）→ 再注入 `entry` → 在这期间执行的 `register()` 才算数。
2. **工厂执行**：拿到 `host`，**登记**贡献，返回 api。这里不要做任何"看得见的动作"。
3. **启用 / 停用**：停用会**收回**所有贡献（插槽项、样式、主题、提示词、事件订阅），但**不重跑工厂**。
4. **卸载 / 删除**：`host.signal` 被 abort —— 长任务（fetch、轮询）应据此退出。

状态机：`pending` → `ready` / `disabled` / `blocked`（前置不可用）/ `error`（加载失败）。
加载失败会被**自动停用并写盘**，原因留在插件卡片上。

## 五、不要读的东西

给 AI 的提示：`AGENTS.md`、`开发文档.md` 是**宿主开发**的规范，体量大。
写插件时你只需要本技能。只有当用户明确要求"改宿主 / 改规范"时才去读那两份。
